# ARIA — Full Build Plan

## What Is ARIA

ARIA (Adaptive Reasoning Interface for Android) is an AI-native Android launcher forked from Lawnchair 2. Instead of just predicting which app you'll open, ARIA predicts what **information** you need and surfaces it proactively as cards on your home screen. Instead of launching Gmail, see your inbox summary. Instead of opening your calendar, see your next meeting with a join button. The AI is ambient, not opt-in — every unlock is a touchpoint.

ARIA is an **Ambient Agent OS**: a skill-based system where each installed app can be queried, summarized, and acted upon without ever opening it. The home screen becomes a context-aware feed of actionable insight cards, powered by LLM reasoning over device context signals.

**Core insight:** Google's agentic features are buried inside the Gemini app. ARIA starts at the launcher level — it *is* the home screen.

---

## Philosophies

1. **Battery-first** — All ML inference and trend analysis runs during a nightly charging window when the user is detected asleep. Daytime execution only applies already-computed decisions.
2. **Privacy-first** — No usage data ever leaves the device unless the user explicitly configures a remote LLM endpoint.
3. **LLM-agnostic** — All LLM calls go through a provider abstraction layer. Swapping Claude for Gemini for Ollama requires zero changes outside the config.
4. **Launcher-native** — Not a widget or overlay. The actual home screen.
5. **Skills over apps** — Instead of predicting which app to open, predict what information to surface and what actions to take.
6. **Open base** — Fork Lawnchair 2 (open source, Kotlin, Pixel Launcher parity) as the shell.

## Agentic Vision: Skills Replace App UIs

### What Is a Skill?

A "skill" is something ARIA can do *with* or *about* an installed app, without the user opening it. Skills have:
- **Trigger**: when to activate (context-based, scheduled, or on-demand)
- **Action**: what to do (query data, perform action, show information)
- **Card**: how to present the result on the home screen

### Skill Discovery Layers (Most → Least Native)

| Layer | Source | Example | Availability |
|-------|--------|---------|-------------|
| 1. Android Shortcuts | `LauncherApps.getShortcuts()` | "New message", "Search" | Today |
| 2. Built-in Skill Packs | Curated by ARIA | Gmail inbox summary, Calendar next event | We build these |
| 3. Intent Skills | Standard Android intents | Share, View URL, Send email | Today |
| 4. MCP Servers | App-hosted MCP endpoints | Full app API access | Future |
| 5. Accessibility | Screen reading + UI automation | Any app, any action | Today (requires permission) |

### Skill Execution Flow

```
Context change (unlock, time change, location)
  → ContextSignalManager emits new signals
  → SkillOrchestrator matches skills to current context
  → For each matching skill:
      → Check if cached result is still fresh
      → If stale: run skill (query data, read notification)
      → LLM summarizes/prioritizes results
      → Emit SkillResult → home screen card
  → LlmProvider ranks and curates the card feed
```

## LLM Provider Strategy

| User Setup | ARIA Provider | Auth | Cost |
|------------|--------------|------|------|
| Google AI Studio (Gemini) | `OpenAICompatibleProvider` | API key | Free tier |
| Claude Pro/Max subscription | `ClaudeProvider` | OAuth token via QR pairing | Subscription |
| Claude API key | `ClaudeProvider` | `x-api-key` header | Per-token |
| Self-hosted Ollama | `OllamaProvider` | Server URL | Free |
| OpenRouter | `OpenAICompatibleProvider` | API key | Per-token |
| OpenAI / GPT-4o | `OpenAICompatibleProvider` | API key | Per-token |

### Provider Architecture

- **`LlmProvider`** — Interface: `complete()`, `streamComplete(): Flow<String>`, `completeWithTools()`
- **`ClaudeProvider`** — Anthropic Messages API, SSE streaming, native tool calling. Two auth modes: API key (`x-api-key`) or OAuth subscription token (`Authorization: Bearer`). Auto-refreshes 8-hour OAuth tokens.
- **`OllamaProvider`** — Remote server (user-configured URL), NDJSON streaming
- **`OpenAICompatibleProvider`** — Generic chat completions endpoint (Gemini, OpenRouter, Ollama OpenAI mode, etc.)
- **`LlmProviderManager`** — Runtime provider selection persisted to DataStore
- **`AriaPrompts`** — System prompt builder with context injection + tool definitions

### Design Decisions

- **OkHttp directly, not Retrofit** — SSE streaming doesn't work well with Retrofit; LLM APIs are 1-2 endpoints each
- **Native tool calling, not text parsing** — Define tools in API requests, receive structured `tool_use` responses
- **Ollama = remote server** — user configures their home server IP/URL; no localhost default
- **Gemini recommended for onboarding** — free tier, one-click API key with Google account

## Phase 2 — Prediction Engine

### Two-Tier System
- **Tier 1 (rule-based):** Fast heuristics from day one — time-of-day buckets, day-of-week, calendar lookups
- **Tier 2 (TFLite):** Trains on 14+ days of user data; gradually replaces Tier 1 (deferred)

### Context Buckets
```kotlin
enum class DayType { WEEKDAY, WEEKEND }
enum class TimeBucket { EARLY_MORNING, MORNING, MIDDAY, AFTERNOON, EVENING, NIGHT }
enum class LocationHint { HOME, WORK, COMMUTE, UNKNOWN }

data class ContextKey(val dayType: DayType, val timeBucket: TimeBucket, val location: LocationHint)
```

### Nightly WorkManager Job
- Runs daily ~3AM when charging
- Pulls last 30 days of events, groups by context key, scores per app
- Writes AppPrediction rows back to Room

## Gotchas

- `PACKAGE_USAGE_STATS` cannot be granted at install — direct user to Settings > Special App Access
- WiFi SSID returns null without location permission — LocationHint defaults to UNKNOWN
- ActivityRecognition returns null without permission — commute detection disabled
- Accessibility Services face Google Play policy scrutiny — document use case
- WorkManager with `setRequiresCharging(true)` defers if not charging — correct behavior
- Daytime prediction path is purely a Room read — must be < 5ms, no ML inference
- Stream LLM responses token-by-token — never make user wait for full response
- Ollama: when away from home on mobile data, fall back to Claude or Gemini
- Widget hosting requires `BIND_APPWIDGET` + system dialog — explain during onboarding
